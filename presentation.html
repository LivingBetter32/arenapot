House rules

Built to never lose money

Never pay twice

Preparations are idempotent per entry — repeating a request returns the same payment, never a new one.

No silent retries

Expired prep, failed tx, missing events → record kept, human decides. Errors never trigger re-payment.

Tamper-evident signing

Server compares the hash of what Freighter signed against the prepared envelope. Changed body or fee-bump wrapper = rejected.

Secrets stay put

API token lives server-side only; signing keys stay in the wallet. Nothing sensitive in the browser.

EXAMPLE · DOUBLE-CLICK ATTACK

nova_kid clicks “Approve & prepare payment” twice in a panic. The server looks up entry #1, finds the payment it already prepared, and returns that same one. Result: one transaction, signed once, for 10 XLM — not 20.

Recovery · instant replay

When things go wrong: “Check payment”

Observed on-chainApp behaviour
SUCCESS + matching payoutsMarks paid — never re-sends
PENDING / UNKNOWN / errorsKeeps the original record; re-check the same hash
Confirmed FAILEDKeeps the receipt; fix cause before a deliberate retry
Expired preparation / NOT_FOUNDRetains record; asks for support — no silent replacement
EXAMPLE · WI-FI DROPS MID-BUY-IN

Entry #1 shows “paying”. The player clicks Check payment — the server finds the transaction hash, reads the ledger: SUCCESS, 9.0 and 1.0 both paid out. Entry flips to paid, the pot grows by 9 XLM. No new payment is created — the old one is simply confirmed.

EXAMPLE · WHY STROOPS + BIGINT

1 XLM = 10,000,000 stroops (integers). So the 10 XLM buy-in = 100,000,000 stroops, split into 90,000,000 (vault) + 10,000,000 (fund).
If we used decimals, 0.1 + 0.2 ≠ 0.3 on a computer — with stroops, it's always exact.

Honest limits

What a production version still needs

  • The vault is custodial. One address, one organizer key holds the pot — fine for a testnet demo, not for real money
  • Production would use a locked escrow contract — the pot pays out to winners by rules, no single custodian
  • A real database instead of orders.json
  • Authentication & ownership checks on checkout routes
  • Rate limiting, stricter request validation, and an audit before any mainnet use
EXAMPLE · WHY CUSTODY MATTERS

Friday Frenzy's pot is 36 XLM sitting in the vault address. If the organizer's key is lost, the pot is frozen forever; if it's stolen, the pot is gone. An escrow contract removes that single point of failure — that's the first thing we'd build before accepting a single real buy-in.
